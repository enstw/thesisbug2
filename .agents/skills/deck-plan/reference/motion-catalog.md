# Motion catalog — 動態變化目錄

分鏡表的「動態」欄填這裡的代碼，一頁一個（最多再加一個轉場）。它決定活潑模式（deck-svg § Lively mode）裡這一頁怎麼逐拍出現；`./fw deck-compile` 會把能自動加的代碼變成 `data-beat`／`data-fx`／`data-enter` 屬性，要手寫的代碼留在分鏡當作意圖，由 deck-svg 的作者加屬性。沒有這一欄、或填 `—`，投影片就是靜態的，整頁一次出現。

機器讀的版本在 `scripts/_deck_motion.py`（`VARIATIONS`）；測試檢查這份文件列了裡面的每個代碼。

## 怎麼選

兩條路，二選一，看的是同一份目錄、同一套措辭：

1. **自己列舉**：寫分鏡時照下表挑。表裡只寫效果：台下看到什麼、動幾秒、多按幾次、需要什麼才成立、什麼時候失效。沒有「封面用 M-CHARS」這種對照，因為那是答案，不是描述；要判斷的是這一頁的事實（第幾頁、標題幾個字、有沒有一句話導語、幾組項目、有沒有數字、講幾分鐘、和前一頁是不是同一個論點）配得上哪個效果。
1. **交給 Jev**：`./fw deck-motion-pick <talk>` 把每一頁變成一題選擇題（只列編譯做得到的代碼），送給 Jev（jev-decide 技能的 runner，付費，要作者確認後加 `--ack`），答案寫回「動態」欄。送出的是事實，不是提示：共用的 state 放目標、全場限制、前提全文、依序的每一頁；每一題放這一頁算出來的事實（位置、是不是分節頁或分節後第一頁、標題字數、導語與字數、項目組數、大數字與是否為關鍵數字、講述分鐘、來源論點是否同前一頁、前後頁的版型與論點）加畫面內容與口說重點，選項就是下表的三欄。沒有 runner 時它仍會產生題目檔，可以手答再用 `--answers` 餵回去。

要用 `M-SCRAMBLE` 凸顯全場唯一的關鍵數字，就在前提加一條 `- 關鍵數字：5,380`；帶這個數字的那一頁會多一句事實「作者標為全場關鍵數字」。沒有這一條，Jev 和作者都沒有理由花掉那唯一一次。

選完跑 `./fw deck-compile <talk>`，再開 `deck.html` 按 `M` 看。

## 代碼

| 代碼 | 台下看到什麼 | 編譯會自動加 | 好處 | 需要什麼、代價 |
| :--- | :--- | :--- | :--- | :--- |
| `M-STEP` | 標題與導語隨頁出現；之後每按一次出一組（一張卡、一個節點或一層，上浮 0.6 秒），收束框最後一拍；按鍵＝組數＋1 | ✓ | 台下只看得到講到的那一格；動作最小 | 組越多按越多次；只有一組或沒有組時和 M-NONE 幾乎沒差 |
| `M-POP` | 同 M-STEP 的拍序，每組從 82% 縮放彈到 100%（0.6 秒） | ✓ | 有邊框或底色的方塊出現時更有份量 | 需要方塊狀元素；段落文字會抖；連頁用會膩 |
| `M-TYPE` | 導語逐字打出 1.6 秒，其餘同 M-STEP | ✓ | 台下跟著字讀，那一句被放慢、被讀完 | 需要一句純文字導語；超過約 25 字打太久；台下等它打完 |
| `M-CHARS` | 標題的字依序彈入（每字錯開 0.04 秒，約 0.7 秒），其餘同 M-STEP | ✓ | 短標題單獨出現時有重量 | 需要標題短（約 12 字內），長了就吵；全場第三次就不稀奇 |
| `M-LINES` | 標題整行從遮罩下升起（每行錯開 0.1 秒），其餘同 M-STEP | ✓ | 動作小而正式；多行標題讀的順序清楚 | 單行短標題看不出和 M-STEP 的差別 |
| `M-COUNT` | 大數字從 0 遞增到位（1.2 秒，保留前後綴、千分位） | ✓ `L-STAT-HERO` | 數字的大小被看見，不只是被讀到 | 需要一個純數字；口徑不同的數字並列時遞增會誤導 |
| `M-SCRAMBLE` | 大數字從亂碼解出（1.2 秒） | ✓ `L-STAT-HERO` | 解出前不知道多大，有懸念；比遞增搶眼 | 需要一個純數字；台下要等它解完；第二次就沒有懸念（全場只保留一次） |
| `M-PUSH` | 進頁時前一頁往左推出、這頁從右滑入（0.5 秒） | ✓ | 兩頁像同一條內容的前後段 | 內容不相連時暗示了不存在的連續；連用會暈（不會連續兩頁用） |
| `M-ZOOM` | 前一頁放大 2.6 倍淡出、這頁放大進來（0.8 秒；手寫 `data-zoom-from` 可指定從哪個元素） | ✓ | 台下讀到「這是剛才那一格的細節」 | 不是前一頁的細節時會誤導；動作大，全場最多兩次 |
| `M-DRAW` | SVG 線條沿路徑畫出來，線畫到哪台下看到哪 | 手寫 `data-fx="draw"` | 自繪圖的結構依講述順序出現 | 版型目錄的流程與時間軸是 DOM，不是 SVG |
| `M-PACKET` | 元素沿 SVG 路徑循環移動 | 手寫 `data-along`（加 `data-rotate` 跟著轉向） | 講到「資料往哪裡去」時畫面正在流 | 要手寫路徑與封包 |
| `M-CONTINUE` | 同 `data-id` 的元素從前一頁位置滑過來（0.8 秒） | 手寫兩頁的 `data-id` | 兩頁的因果用位置接起來，台下不用重新找 | 兩頁都要標；沒有共同元素就沒東西可接 |
| `M-REGROUP` | 同一批卡片換 class 重排，從舊位置飛到新位置 | 手寫 `data-relayout="n:cls …"` | 同樣的事實換個分類看，一頁講完 | 要寫兩套版面 class |
| `M-MORPH` | SVG path 變形成另一個形狀 | 手寫 `data-morph="n:#sel …"` | 變形的過程本身就是說明 | 要畫兩個以上形狀 |
| `M-NONE` | 不標拍，整頁一次出現；按一次換下一頁 | ✓（什麼都不加） | 零按鍵；台下一眼看到整頁 | 好幾組內容時台下會先讀完全部，不跟著講者 |

## 全場的限制與拉鋸時的取捨

- 每頁一個代碼；要加轉場就再寫一個 `M-PUSH` 或 `M-ZOOM`（例：`M-POP M-PUSH`）。
- `M-SCRAMBLE` 全場一次，`M-ZOOM` 最多兩次，連續兩頁不要同一種轉場——花俏的效果用第二次就失效。這三條 Jev 的每一題看不到別題的答案，所以由 picker 在答案回來後套用並列出改了哪幾頁；自己選時照著數。
- 台下約十秒要看懂一頁；拍越多講者按越多次。
- 兩個效果拉鋸時取較克制的那個，克制的順序：`M-NONE`、`M-STEP`、`M-LINES`、`M-COUNT`、`M-TYPE`、`M-POP`、`M-CHARS`、`M-SCRAMBLE`、`M-PUSH`、`M-ZOOM`。picker 在前兩名差距小於 0.15 時自動這麼做並印出來；信心低於 0.6 但差距夠的，照 Jev 的選，只印提醒（選項有八到十個，分散是常態，差距才是真的歧義）。這條不送給 Jev，是我們自己的取捨。
- 版型的收束框永遠是最後一拍；編譯會把拍號壓成連續的，不會有「按了沒反應」的空拍。

## 編譯後長什麼樣（手寫投影片時照這個寫）

`M-STEP` 把版型的 `.rise d1`–`.d4` 讀成拍號：沒有 dN 的是第 0 拍（隨頁），dN 是第 N 拍，再壓成連續。`M-POP` 給 `.card`、`.tl`、`.flownode`、`.tier` 等方塊加 `data-fx="pop"`；`M-TYPE` 給 `.lead`／`.hero__sub`／`.onesentence` 加 `data-fx="type" data-dur="1.6"`；`M-CHARS`／`M-LINES` 給 `h1`／`h2` 加 `data-fx="chars"`／`"lines"`；`M-COUNT`／`M-SCRAMBLE` 給 `.stat-hero__num` 加 `data-beat="1" data-fx="count"`／`"scramble"`；`M-PUSH`／`M-ZOOM` 給 `<section>` 加 `data-enter`。元素保留原本的 class，引擎執行時自己拿掉 `.rise`。完整屬性表在 deck-svg SKILL.md § Lively mode。
